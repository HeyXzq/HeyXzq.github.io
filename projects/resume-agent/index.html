Resume Tailoring Agent

A Claude Code skill that maps your real experience to a job description, rewrites the wording for the role, and keeps the result truthful and on one page.

01

The problem

Similar roles describe the same skills in different words, so job seekers end up rewriting the same resume for every application.

Doing it by hand takes time. Generic AI rewriting is faster but creates new problems: it runs past one page, blurs the line between what you did and what sounds good, and you have to remember an exact tool name to use it.

I built this skill in my spare time to fix my own application workflow first, then shared it with friends who were job hunting too.

02

How it works

  1. Resume + jobStart from your existing resume and the target job description.
  2. Map capabilitiesMatch each requirement to evidence already on your resume.
  3. Rewrite, don't inventAdjust wording toward the role. No new projects, skills, or impact.
  4. One-page budgetFit everything inside a fixed one-page content budget.
  5. Tailored resumeA role-specific version in about five minutes.

The two highlighted steps are the guardrails that make the output trustworthy.

03

Same facts, different story

Here's what tailoring looks like in practice: two real bullets from my own resumes, describing the same project for two different roles.

Tailored for a product role

Led a five-person team to develop and pitch Allianz Risk Compass, a subscription travel-risk product using proprietary claims data; owned the product narrative, GTM plan, and financial model ($9.8M Year 1 revenue, 32% base-case IRR on $15M CapEx).

Tailored for a growth role

Led a five-person team to build and pitch Allianz Risk Compass, a subscription travel-risk product, to Allianz executives, owning a multi-channel acquisition plan (paid search, SEO, display, referrals, social) for risk-averse customers over 50.

What gets emphasized changes with the role. The underlying facts never do.

04

Shaped by testing

I used it on my own applications first, then shared it with peers. Two problems showed up quickly, and each one became a feature:

One-page content budget

Early outputs ran too long. A fixed content budget now keeps every tailored version to a single page.

Intent-based triggers

People couldn't remember the skill's name. Now plain requests like “tailor my resume,” “tailor for this job,” or “resume improve” start it.

Feedback from peers has been positive so far. This is small-scale testing, not a launched product, and I treat it that way.

05

What's next

  • Confirm facts with the user, in a structured way, before rewriting.
  • Explain every change it makes.
  • Offer optional ATS-friendly formatting.
  • Track usage and repeat use.
  • Test whether it improves application outcomes, not just speed.

06

What I learned

Find a real problem, build quickly, test with real users, then iterate on the constraints.

Both of the most important changes, the one-page budget and plain-language triggers, came from watching people use the tool, not from my first design.
